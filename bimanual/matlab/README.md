# Bimanual task-priority exercise template

This folder contains the MATLAB template for controlling two Franka Emika Panda manipulators with an incremental task-priority architecture. Both arms use the same mechanical model stored in `panda.mat`; two `PandaArm` instances distinguish them through their fixed base poses in the common world frame.

## Main components

- `BimanualMain.m` configures the exercise, defines the named actions and runs the control loop.
- `PandaArm.m` stores one arm state, loads the rigid-body model and computes its transforms and Jacobian.
- `BimanualSim.m` integrates both joint-velocity vectors and refreshes the two arm models.
- `ActionManager.m` stores named strict-priority task stacks and applies the iCAT recursion.
- `UDPInterface.m` exchanges measurements and commands with the physical setup or sends simulated joint positions to PyBullet.
- `SimulationLogger.m` records the two arm states and the selected task signals.
- `tpik/TaskTool.m` implements the current Cartesian tool-pose objective.
- `tpik/TaskManipulability.m` implements a smooth lower-bound inequality for the manipulability of one arm.

## Central notation

The complete control vector is

```matlab
q_dot = [q_dot_left; q_dot_right];
```

Each arm contributes seven joint velocities, so `q_dot` is 14-by-1. Every task follows

```matlab
x_dot = J*q_dot;
```

where `J` has fourteen columns ordered as `[left arm, right arm]`. Cartesian task vectors use `[angular; linear]` ordering.

Transform names follow `aTb = ^a T_b`: the transform maps coordinates expressed in frame `b` into frame `a`. The principal frame letters are `w` for world, `b` for arm base, `e` for end effector, `t` for tool, `o` for object and `g` for goal.

`CartesianError(aTb,aTc)` returns the angular and linear geometric errors that bring frame `c` into frame `b`, expressed in the common frame `a`. The proportional gain in `TaskTool` converts those errors into velocity references.

Each `TaskTool` is bound directly to its `PandaArm` at construction. The additional `"left"` or `"right"` identifier is used only to place the arm's 6-by-7 Jacobian in the correct columns of the complete 6-by-14 bimanual Jacobian. Consequently, task update methods require no `BimanualSim` argument.

System-velocity saturation is enforced inside the shared iCAT recursion. Each `PandaArm` provides `q_dot_max = 2 rad/s` for its seven joints; `ActionManager` combines the two limit vectors in `[left arm; right arm]` order and builds the corresponding symmetric lower limits. After every priority level, iCAT returns the velocity range still available to the following tasks.

`PandaArm.computeJacobianDerivatives` evaluates the [6x7x7] tensor `dJdq` with forward finite differences without changing the stored robot state. `PandaArm.computeManipulability` uses this tensor to return Yoshikawa's manipulability and its [1x7] joint-space gradient. These relatively expensive quantities are evaluated only when requested by a task or analysis routine.

`TaskManipulability` is fully active when manipulability is at or below `minimumManipulability`, transitions smoothly to zero activation between that value and `activationThreshold`, and is inactive above the latter. Its [1x7] local gradient is embedded in a [1x14] Jacobian according to the selected arm. The example main uses initial values 0.06 and 0.07; these values should be calibrated after observing the manipulability range generated by the chosen tool transform and Jacobian scaling.

## Named actions

An action is a cell array of tasks ordered from highest to lowest priority. Register and select actions using descriptive strings:

```matlab
actionManager = ActionManager(bimanualSystem);
actionManager.addAction("go_to_object", {leftToolTask, rightToolTask});
actionManager.setCurrentAction("go_to_object");
```

## Running the exercise

Add this template directory to the MATLAB path or set it as the current folder, then run:

```matlab
BimanualMain
```

The template targets MATLAB R2025 or later and uses Robotics System Toolbox for the Panda model. UDP communication uses DSP System Toolbox objects. With `realRobot = false`, joint positions are sent to the PyBullet visualization endpoint on localhost.
